# Website closeout and routine checks

This is a working checklist, not a completed audit or scheduled automation. Do not mark items complete without evidence. Keep account emails, recovery details, payment information and private agreements outside this public repository.

## Before releasing a customer-facing change

- Run the Python site checks, Python tests, JavaScript syntax check and JavaScript interaction tests documented in the README.
- Review only the intended changes; confirm the phone remains 843-793-8806.
- Preview at narrow and wide widths, enlarged text and a short landscape viewport. Check that headings, project descriptions, feedback cards and call controls remain readable.
- Use only the keyboard: skip link, menu, section links, contact actions and footer. Escape should close the menu; focus should not remain in hidden navigation.
- Check reduced-motion preferences and visible focus on light and dark sections.
- With JavaScript disabled, confirm navigation and telephone links remain available.
- After approved publication, verify the successful GitHub Pages deployment and the actual changed live content. A successful local test does not prove release.

## Real-phone acceptance test (still requires a person/device)

- On iPhone and Android, share the homepage link and inspect the existing branded preview. Messaging apps can retain cached previews; document the app and date.
- Follow the link. Test the header and hero estimate buttons, contact phone, fixed mobile call button and footer phone.
- Check that each telephone action presents 843-793-8806. Place one coordinated test call with the owner, not repeated unattended calls.
- Open/close the menu, rotate the device, enlarge text and follow a section link. In short viewports the persistent call button moves into page flow to leave room for content.
- Test copying the number and following Instagram links, including the signed-out experience.
- Check a missing URL reaches the branded recovery page and its links work.

## Owner confirmation needed

- Verify current license details and insurance wording, and whether any documentation may be published. Existing website claims are not independent verification.
- Confirm hours, emergency availability, estimate conditions and appointment expectations before promising them online.
- Confirm the photographed locations and identifiable people are approved for website use. The Instagram archive preserves sources; it does not by itself establish permission.
- Keep Instagram comments identified as community feedback unless customer relationships are verified. Do not add invented ratings or customer-review structured data.
- Confirm Google Business Profile ownership/details and actual Search Console indexing/performance in the authorized accounts.
- Confirm the domain renewal date, payment responsibility after the first year and account access in a private handoff. Do not assume that repository or domain ownership has transferred.

## Suggested monthly review (not automated)

- Verify homepage, contact links, Instagram source links, preview image and custom 404.
- Review recent GitHub Pages runs and investigate failed deployments before publishing again.
- Review Search Console indexing and performance; record the date and observed issues privately.
- Ask whether hours, service areas, credentials, phone or photos need updating.
- Check for new, permission-cleared project material and genuine customer reviews.

Set a domain-renewal reminder after confirming the actual expiration date and the responsible person. Store recovery methods in the responsible account owner's password manager, not here. See the README for the reverting-commit recovery procedure.
